# crm: the reference project

A small CRM (deals, tasks, an audit trail) built with machinery v2 from the design up: a Go HTTP
service on a real Postgres. The design lives in `design/` and `contracts/`; `design/gen/` is
generated by `machinery gen` and never edited. `design/owed.yaml` lists everything not proven
yet. The service takes every transition from the generated tables (`internal/fsm` drives them;
`internal/api` implements the named guards, actions and actors). Tables are read from
`MACHINERY_TABLES_DIR` when set, else `CRM_TABLES_DIR`, else `design/gen/tables`; a table that
names a unit the service does not implement stops it at start.

## Commands

| Command | Does |
|---|---|
| `make` | Lists the targets. |
| `make up` | Starts Postgres 17 (container `machinery-crm-pg`, empty on every start) and waits until healthy. |
| `make serve` | Builds `.bin/crm` and runs it against that database. |
| `make e2e` | The end-to-end suite: the real binary over HTTP against the real Postgres. Needs `make up`. |
| `make check` | gofmt, `go vet`, `machinery check`. |
| `make evidence` | The suite through `machinery run`: a receipts file for the current commit. |
| `make verify` | The end gate: `machinery landing --base $(BASE)` (check with the ratchet, the whole suite through `run`, `verify`). `BASE` is the ref the change started from (default `HEAD~1`); it must contain this project. |
| `make probe` | `machinery probe --max $(MAX)`: mutates the tables the service reads and expects the suite to notice. |
| `make psql` | A psql shell as the admin role. |
| `make down` | Stops Postgres and removes the container and its data. |

`MACHINERY_TOOLS` names the directory of the pinned tools (modelith, xstate); it defaults to the
repository's `.bin`, where `machinery` itself is expected too (`make build` at the root).

## Ports and configuration

- Postgres: `127.0.0.1:15432`, database `crm`, admin role `crm_admin` (migrations only), app
  role `crm_app` (the service).
- Service: `CRM_ADDR` (default `127.0.0.1:18080`), `CRM_DATABASE_URL`, `CRM_ADMIN_DATABASE_URL`.
- `GET /healthz`: 200 `{"status":"ok"}`, or 503 `{"code":"STORE_UNAVAILABLE","message":"..."}`.

## Identity

The caller is named by the `X-User-Id` header: a missing, malformed or unknown id is 401. This is
enough for an example and is not authentication.

## The suite and the owed list

`e2e/transitions_test.go` walks the committed tables (`design/gen/tables`, never
`MACHINERY_TABLES_DIR`): one subtest per transition, ignore and clause case, which arranges a
record in the source state, fires the event over HTTP, checks the answer and the row, and claims
only the effects it observed (each audit effect as exactly one audit row). `audit_test.go`,
`adversary_test.go` and `scenarios_test.go` prove the invariants, the abuse failure modes and
the scenarios. The suite honors `MACHINERY_ONLY`; under `machinery probe` it runs only the
subtest of `MACHINERY_PROBE_CASE`.

After a change: `make up`, `make evidence`, `machinery owed sync --prune-only`, commit,
`machinery verify`. `machinery owed list` says what is still unproven and why.

## Clean up

`make down`. Afterwards `docker ps -a --filter name=machinery-crm` prints no container.
